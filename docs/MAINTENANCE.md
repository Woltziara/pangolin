# 0.4.10 维护范围

本轮目标是降低自用客户端的维护成本，保留 ArkTS → N-API → HEV / Xray 的生产路径和既有功能。语言数量和代码行数不是验收指标。

## 实现收敛

- 原生桥绑定 `CORE_LOCK.json` 的 Xray ABI；删除没有消费者的新版 ABI 兼容、sing-box、旧 tun2socks、子进程 / memfd 启动、TUN 嗅探和实验探针代码。
- `stopHevTun` 从命名到实现只负责 HEV；删除引擎选择分支和重复的引擎状态。ArkTS 调用与类型声明同步更新。
- 删除没有 App 消费者的 N-API 方法。16 个保留接口负责连接、停止、状态、socket 保护、原子文件替换和 App 流路由。
- 接口类型只在原生模块声明中维护。ArkTS 桥引用这些类型，保留按 owner 停止的保护。
- 保留启动取消、异步回调归属、停止超时、失败关闭、原子写入和凭据保护；这些机制有实际错误场景和行为测试支撑。

## 开发工具与测试承接

| 退役内容 | 当前消费者 / 验证方式 |
| --- | --- |
| `r1-build.sh`、个人签名/安装脚本、阶段测试入口 | `scripts/build.sh` 负责 unsigned 构建；签名交给本地 DevEco；本轮不自动操作手机 |
| 旧 `scripts/lib` Python 状态机及其模拟测试 | Node 测试直接执行 ArkTS 生产源码中的连接、策略、数据和诊断逻辑 |
| 针对旧页面文字和代码片段的快照断言 | 保留现有 Node 行为测试和必要的跨层接线检查；真实界面仍需手机验证 |
| 复制的 fd release 测试模型 | 从实际 `napi_init.cpp` 提取并编译，验证并发释放与 fd 复用后不误关 |
| 不再使用的内核适配器和旧构建文档 | Git 历史保留；当前构建以 `docs/BUILDING.md` 与版本锁定为准 |

没有把测试删除当成修复通过：测试对象随旧开发工具一起退役，当前通过声明只覆盖新的明确范围。当前默认入口运行全部 `*.test.mjs`，包括原手工列表漏掉的测试文件。

## 边界

- 不改节点、订阅、规则、HUKS 存储格式，也不改变单双通道及备用策略。
- App 指定节点的手机权限限制仍存在；本机原生测试通过不解除平台限制。
- 保留核心依赖版本和补丁。本轮重建证明源码与锁定内核一致，未进行依赖升级。
- 手机连接、后台耗电与持续使用体验须以新版本真机结果为准；代码精简不冒充速度或耗电提升。
