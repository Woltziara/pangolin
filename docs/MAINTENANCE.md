# 0.5.41 维护入口与精简范围

当前基线由独立真机回读确定为 0.5.39。保留后续已加入的数据事务、socket 借用生命周期、owner 归属、网络恢复和故障现场能力。

本轮目标是降低自用客户端的维护成本，保留 ArkTS → N-API → HEV / Xray 的生产路径和既有功能。语言数量和代码行数不是验收指标。

## 实现收敛

- 原生桥绑定 `CORE_LOCK.json` 的 Xray ABI；删除没有消费者的新版 ABI 兼容、sing-box、旧 tun2socks、子进程 / memfd 启动、TUN 嗅探和实验探针代码。
- `stopHevTun` 从命名到实现只负责 HEV；删除引擎选择分支和重复的引擎状态。ArkTS 调用与类型声明同步更新。
- 删除没有 App 消费者的 N-API 方法。23 个保留接口负责连接、停止、状态、socket 保护、原子文件替换、App 流路由和持久错误记录。
- 接口类型只在原生模块声明中维护。ArkTS 桥引用这些类型，保留按 owner 停止的保护。
- 保留启动取消、异步回调归属、停止超时、失败关闭、原子写入和凭据保护；这些机制有实际错误场景和行为测试支撑。

## 边界

- 不改节点、订阅、规则、HUKS 存储格式，也不改变单双通道及备用策略。
- App 指定节点的手机权限限制仍存在；本机原生测试通过不解除平台限制。
- 保留核心依赖版本和补丁。本轮重建证明源码与锁定内核一致，未进行依赖升级。
- 手机连接、后台耗电与持续使用体验须以新版本真机结果为准；代码精简不冒充速度或耗电提升。

## 本地维护入口

App 的“诊断 → 保存故障现场”是被动读取入口，不触发测速或重连。报告包括版本、源码身份、当前连接 owner、运行指标、错误记录和系统退出事件。

连接明确选定的开发设备后，可以一次性读取维护包：

```sh
python3 scripts/maintenance.py --target <HDC设备标识> --output <私有输出目录>
```

脚本仅读取允许的诊断文件，不读取节点、订阅、配置或 HUKS 密钥，不启动服务，不后台轮询。它需要已有 HDC 调试授权；发布包或不同系统权限可能限制沙箱读取，缺失文件会显式列出。手机断开电脑后仍自行保存日志。

错误日志由 UI、VPN 和订阅任务进程共用，native flock 防止并发覆盖，每条追加 fsync。保留 warn/error/fatal、UI 操作异常、未捕获异常及未处理 Promise rejection；原生桥的 LogWarn/LogError 使用同一持久记录器。包含时间、进程、组件、消息和可获得的堆栈。私密格式参数直接遮蔽，已知凭据字段、URL、授权头、IPv4/IPv6、UUID 和域名形态字符串（保留代码文件名）在写入前脱敏。脱敏是防护措施，维护包仍应视为私人材料。

容量为四段、每段 8 MiB，总上限 32 MiB；重开 App 后保留，不按天过期，容量满后轮换最旧段并留下轮换记录。报告最多附带最近 500 条，同时标明总量和省略量；脚本取回全部保留段。已有“清理日志”操作也清理这些错误段。普通运行指标继续保持 48 小时 / 4 MiB 的独立限制。

这是可诊断性增强，不承诺捕获每一次失败：突然断电、进程强杀、存储写入失败、尚未接入的第三方内核内部日志仍可能有缺口。OS 崩溃/卡死/退出元数据单独保留最近 32 条；没有默认启用 Xray 原始访问日志、请求正文或流量解密。需要特定内核问题时再进行有界专项诊断。
